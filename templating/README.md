# Методы API и таблицы

## Методы API

Текущий пользователь в ЛР3 фиксирован: ID 1. Регистрация не меняет текущего пользователя; вход и выход пока являются заглушками.

| Метод | URL | Вход | Результат |
|---|---|---|---|
| GET | `/api/smart_devices` | `mean_max >= 0` — максимум E(X) | 200, список только `published`, сортировка ID по возрастанию; `is_owner` 0/1 |
| GET | `/api/smart_devices/feed` | Необязательные `id > 0`, `next=true/false` | 200, одна опубликованная карточка; 404 при пустой ленте |
| GET | `/api/smart_devices/draft` | Без ID и query-параметров | 200, единственный черновик текущего пользователя; 404, если его нет; ничего не создаёт |
| POST | `/api/smart_devices` | `multipart/form-data`, поля ниже, файлы `image`, `video` | 201, новый черновик; 403, если черновик уже существует |
| PUT | `/api/smart_devices/{id}/publication` | Пустое тело либо `{}` | 200, публикация своего заполненного черновика; 403 при неверном состоянии |
| DELETE | `/api/smart_devices/{id}` | Без тела | 200 без тела, логическое удаление своего черновика или публикации |
| POST | `/api/smart_devices/{id}/likes` | JSON `{"value":1}` или `{"value":0}` | 200, `device_id`, `liked`, `likes_count` |
| POST | `/api/users` | JSON `username`, `password` | 201, ID/имя/дата; 403 при занятом имени |
| POST | `/api/users/login` | Заглушка | 200, аутентификация предусмотрена в ЛР4 |
| POST | `/api/users/logout` | Заглушка | 200, деавторизация предусмотрена в ЛР4 |


Лента без ID возвращает первую запись. С ID без `next` возвращает именно её. С `id&next=true` возвращает следующую по возрастанию ID; после последней — первую. Если исходный ID недоступен, возвращается 404, а не переход к другой записи. `next=true` без ID — 404.

### Данные создания устройства

`POST /api/smart_devices` принимает `multipart/form-data`:

| Поле | Требования |
|---|---|
| `title` | Обязательная строка, 1–255 символов |
| `description` | Обязательная строка, 1–500 символов |
| `traffic_mean` | Обязательное конечное число >= 0, средний трафик E(X) |
| `traffic_variance` | Обязательное конечное число >= 0, дисперсия D(X) |
| `model` | Необязательная строка до 100 символов; по умолчанию пустая |
| `type_label` | Строка 1–100 символов; по умолчанию «УМНОЕ УСТРОЙСТВО» |
| `image` | Обязательный файл JPEG/PNG/WebP; по умолчанию до 10 МиБ |
| `video` | Обязательный файл MP4/WebM; по умолчанию до 50 МиБ |

Пробелы по краям текстовых полей удаляются. Неизвестные и повторяющиеся поля формы запрещены. ID, автор, статус, даты и ключи файлов назначаются сервером. Файлы сохраняются в MinIO, в БД записываются их ключи. В JSON передаются только ключи медиа; ссылки для HTML-страниц формируются отдельно из ключей.

У пользователя может быть только один черновик. PUT публикации принимает пустое тело либо `{}`, проверяет заполненность черновика и меняет статус и дату публикации. Редактирование полей этим методом не предусмотрено. Разрешены переходы `draft → published`, `draft → deleted`, `published → deleted`. Публиковать и удалять запись может только её автор. При логическом удалении строка, файлы и лайки сохраняются.

### Лайки и регистрация

Лайк доступен только для опубликованного устройства. `value` — строго целое число 0 или 1. Повторный запрос с 1 не создаёт второй лайк, повторный запрос с 0 не меняет уже снятый лайк. Ответ: `device_id`, `liked` (0/1), `likes_count`.

Регистрация принимает `username` (3–100 символов: буквы, цифры, подчёркивание, точка, дефис) и `password` (8–128 символов). Дополнительные поля запрещены. Пароль сохраняется как scrypt-хеш с индивидуальной солью. Ответ содержит только `id`, `username`, `created_at`.

### Поля ответа карточки

Список, лента, черновик, создание и публикация используют одну схему:
`id`, `title`, `type_label`, `model`, `description`, `image_key`, `video_key`, `traffic_mean`, `traffic_variance`, `created_at`, `formed_at`, `creator_id`, `is_owner`, `liked`, `likes_count`.

`is_owner` равен 1, если автор совпадает с текущим пользователем, иначе 0. `liked` показывает лайк текущего пользователя, `likes_count` — общее число лайков устройства. `status` устройства не передаётся в JSON. Поля с отсутствующим значением остаются в ответе как `null`; пустая строка остаётся строкой. Если записи нет, возвращается пустой 404. Пустой список возвращается как `[]` с кодом 200.

## Таблицы и все поля

### `users` — модель User

| Поле | Тип | Назначение |
|---|---|---|
| id | integer PK | Серверный идентификатор |
| username | varchar(100), NOT NULL, UNIQUE | Имя пользователя |
| password_hash | varchar(256), NULL допустим | scrypt-хеш; у старых демо-пользователей может отсутствовать |
| created_at | timestamp, NOT NULL | Дата создания UTC, назначается сервером |

### `smart_devices` — модель SmartDevice

| Поле | Тип | Назначение |
|---|---|---|
| id | integer PK | Серверный ID |
| title | varchar(255), NOT NULL | Название |
| type_label | varchar(100), NOT NULL | Тип устройства |
| model | varchar(100), NULL | Модель устройства |
| description | text, NULL | Описание; API новых записей требует заполнение |
| status | varchar(20), NOT NULL | draft / published / deleted; CHECK |
| image_key | varchar(500), NULL | Имя объекта изображения в MinIO |
| video_key | varchar(500), NULL | Имя объекта видео в MinIO |
| traffic_mean | double precision, NULL | E(X), >= 0; API требует значение |
| traffic_variance | double precision, NULL | D(X), >= 0; API требует значение |
| created_at | timestamp, NOT NULL | Создание, UTC |
| formed_at | timestamp, NULL | Публикация, UTC |
| completed_at | timestamp, NULL | Логическое удаление, UTC |
| creator_id | integer FK users.id, NOT NULL | Автор |

Индекс `uq_device_creator_draft`: UNIQUE (`creator_id`) WHERE `status = 'draft'`. CHECK `ck_device_status` ограничивает значения статуса, `ck_device_traffic` — неотрицательные значения трафика. Разрешённые переходы между статусами контролирует API.

### `likes` — модель Like

| Поле | Тип | Назначение |
|---|---|---|
| id | integer PK | ID лайка |
| user_id | integer FK users.id, NOT NULL | Пользователь |
| device_id | integer FK smart_devices.id, NOT NULL | Устройство |

UNIQUE (`user_id`, `device_id`). Связи без каскадного удаления. Отмена лайка удаляет строку связи; устройства удаляются исключительно логически.

Связи: `users` 1 → 0..* `smart_devices` (авторство), `users` 1 → 0..* `likes`, `smart_devices` 1 → 0..* `likes`. Таблица `likes` связывает пользователей и понравившиеся устройства отношением многие ко многим.

### `alembic_version` — служебная таблица

| Поле | Тип | Назначение |
|---|---|---|
| version_num | varchar(32), PK | Текущая ревизия структуры БД |
